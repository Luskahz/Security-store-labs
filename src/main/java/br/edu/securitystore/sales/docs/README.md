# Vendas e entrega

Responsável por pedidos, pagamento fictício e status de entrega. `OrderService` coordena os fluxos e a transação de compra. O pedido guarda IDs e um retrato de cliente/produto, sem relações JPA com outros contextos. `CustomerLookup` e `ProductReservation` são ports implementados por adapters que chamam as APIs internas de IAM e catálogo.

Fluxos HTTP: `GET/POST /api/orders`, `POST /api/orders/{id}/pay` e `GET/POST/DELETE /api/payment-cards`. A compra exige perfil de entrega completo e copia os dados de destino para o pedido. A resposta do pedido inclui o resumo de entrega do módulo `logistics`; o status, o rastreio e a previsão não são mantidos no agregado de vendas. Cartões fictícios são persistidos por identidade em `saved_payment_cards`; somente token local e últimos quatro dígitos são armazenados. O número digitado é descartado e não há gateway financeiro. O usuário só pode pagar pedidos próprios e acessar seus próprios cartões; SALES_ORDER_READ_ALL e LOGISTICS_DELIVERY_READ consultam os destinos necessários à operação. DTOs HTTP são separados do domínio e da persistência.
